## Dependencies & Execution Order

### Phase Dependencies

- Phases 1–2 are foundational: nothing downstream composes without events, llm.py, config, findings, sanitizer, and the fan-out stages.
- Phase 3 (mutex) composes Phase 2's stages (release timing references the last lease-covered call).
- Phase 4 (terraform) is independent of Phases 2–3; the archive contract (T028) lands in Phase 4 while its implementation (T029) sits in Phase 5 because the write must know the shadow ordering (T035 pins it; write-after-shadow is the correctness constraint).
- Phase 5 (shadow wiring) needs Phases 1–4. Phase 6 (harness) needs Phase 2's full pipeline + corpus (T037/T038 parallelizable with Phases 3–5).
- Phase 7 (calibration) needs EVERYTHING in Phases 1–6. Phase 8 needs the Phase-7 exit ruling. Phase 9 is independent of Phase 8 (only needs Phase 4's archive/index) and can run in parallel with Phase 7/8 as a separate lane.

### Parallel Opportunities

- Within every phase, `[P]` creator tasks run in parallel lanes (disjoint files, one worktree per lane per batch-loop.md).
- Phase 6 harness/scorer/probe run as a parallel lane while Phases 4–5 land.
- Phase 9 (replay) is the long pole's natural parallel companion to Phase 7 calibration.

### Policy notes

- P2 pairing: each test-first creator + its implementer ship as ONE PR; both tickets stay individually started/commented.
- Every terraform-changing PR lands WITH its contract-test update (three-way contract discipline, HLD §8 checklist 2 precedent).
- Deploys and flag flips (T042–T044, T050, T056) are operational tasks: `tf-*` tags and MULTI_AGENT activation require Mars's explicit approval; the tag push starts an automatic HCP apply.
